## Verify the route before claiming control

| Capability | Establish from observed access | If unavailable |
| --- | --- | --- |
| Read target | Actual project/root, source revision/dirty state, instructions and current records | Use supplied snapshot and identify the exact missing material. |
| Write target | Authorized destination and protected local/newer/foreign work | Prepare complete proposed records or patch for manual reconciliation. |
| Run/delegate | Callable supported tool, actual working directory, permissions, result channel and active writer | Deliver the full manual task packet. |
| Collect/review | Actual source changes, records, logs/checks, candidate identity and run status | Keep required checks NOT RUN/BLOCKED and request exact evidence. |

A local Codex binary does not establish access to a different laptop, VPS, terminal or checkout. Inspect the installed interface and supported execution/resume mechanism; do not invent commands, flags, session IDs or connection endpoints. Reuse authorized connectors, a real remote execution tool or existing configured SSH where appropriate. Missing access does not authorize installing a bridge, exposing a new service or collecting broad credentials.

Before dispatch, reconcile current records, baseline, running ownership and uncertain effects. A disconnected channel does not prove the process stopped. Reuse an active session only through a verified interface; otherwise reconcile its writer before another run. One controller owns continuation. Give independent writers separate files/workspaces and integrate a stable candidate.

## Coordinate the shared loop

Prepare the complete task and reference closure, transfer through the verified route, dispatch with actual authority/limits, collect real evidence, review against the declared two-plane gates and send ordinary in-scope corrections. Resolve routine executor questions from accepted records. Ask the owner only about a consequential unresolved product/cost/access/irreversibility decision or genuine blocker; never bypass tool-enforced permission refusal.

Use the shared no-progress, checkpoint and stop rules. Track task and actual run IDs, current writer, candidate, permissions, budget, last useful result, pending effects and next action. Review submitted claims against actual files and execution output. At completion deliver current docs, changes, full findings/gates and evidence through the verified return channel. A file in Dot's workspace has not automatically reached ChatGPT.

## Missing access and unattended limits

If connection, native execution or return access is missing, still finish the same complete documents and usable manual packet. Explain the precise unavailable route and exact next transfer action. Do not fake remote dispatch or pause independent design work for a connection questionnaire.

This pack does not ship a connector, daemon or unattended supervisor. One active authorized run can iterate through ordinary corrections; persistence after disconnect/end requires real supported tooling with tested interruption/resume, duplicate dispatch, unknown effects, usage limits, cancellation and permission handling. Configured schedules/backups are not observed successful runs. Claim connected or unattended capability only for the actual tested environment.
