# Mode 2: ChatGPT + Codex, manual exchange

Apply [BASE.md](../BASE.md). ChatGPT develops the product and current planning record with the owner, prepares complete assignments and reviews actual results. Codex works in the actual application checkout and returns source, current documents and evidence. The owner transfers packets unless an established authorized route performs that step.

[HANDOFF.md](../../skills/notchlore/references/HANDOFF.md) owns readiness, complete task contents, exact file lifecycle, safe staging, short initiation and return. [CODEX.md](../../skills/notchlore/references/CODEX.md) owns execution. Read both before dispatch; do not create a competing protocol.

After a concrete scope is accepted and the document gate passes, produce the actual self-contained ZIP, its exact receiving project/fresh staging path and one initiation prompt. Do not ask whether to write an already requested packet. The executor has no planning-chat access. Uploading a pack to ChatGPT does not install a skill or place application files on a VPS.

Validate the packet and baseline before reconciliation into existing document owners. The next owner action is the exact transfer/entry step supplied with that packet. A task for an empty workspace includes all required inputs and protects anything discovered there.

When results return, read the actual source/diff, docs and evidence. Reconcile the planning view, prepare an authorized correction for remaining gaps or close at the accepted gate. Manual mode needs another file transfer after an active run ends; prompt text cannot perform that relay in the background. Dot can later replace the transport using the same records if real access is established.
