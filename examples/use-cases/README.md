# Ten ways to use Notch Lore

Start with the work you have in front of you. These are worked examples you can adapt. The packet and scoring walkthroughs also run against the fixtures included with the project.

| What you want to do | What the walkthrough covers |
| --- | --- |
| [Document an existing project](02-document-a-project.md) | Turn source, fixtures and observed behavior into a maintainable current-state document. |
| [Design a new feature](03-design-a-feature.md) | Take a user request through interaction design, compatibility and acceptance checks. |
| [Design a better interaction with ChatGPT](05-design-with-chatgpt.md) | Work through an ambiguous screen in chat and leave with a testable UX decision. |
| [Refactor without changing behavior](10-refactor.md) | Move a duplicated rule behind one owner and compare the public behavior before and after. |
| [Guide Codex through a task](06-hand-off-a-task.md) | Set Codex up with a checked baseline, a bounded assignment and a return you can review. |
| [Review what an agent delivered](07-review-a-return.md) | Use one discriminating input to challenge a passing test report. |
| [Decide whether a version is ready](08-assess-readiness.md) | Read a score, an unknown dimension and a mandatory gate together. |
| [Choose a first version](01-shape-an-idea.md) | Start with a user and a decision. Leave with a small outcome someone can try. |
| [Change an accepted requirement](04-change-a-decision.md) | Replace individual reminders with a digest and trace the consequences. |
| [Resume interrupted work](09-resume-work.md) | Establish what already happened before retrying a job. |
